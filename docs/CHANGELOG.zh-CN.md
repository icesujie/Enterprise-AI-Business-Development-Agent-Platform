# 项目变更日志

**项目：** Enterprise AI Business Development Agent Platform（企业级 AI 商务拓展智能体平台）  
**主要记录：** `CHANGELOG.en.md` 英文工程记录  
**翻译：** 本中文文档

本变更日志记录重要产品、架构、安全和业务能力里程碑。日期来自现有仓库历史。本文有意排除底层提交、日常重构、Bug 修复和仅测试变更。

## 2026-08-07 — Phase 0：基础和架构设计

### 新增能力

- 定义企业级 AI 商务拓展平台的产品愿景。
- 确定 Sari Arta 商用厨房工程为第一个验证业务。
- 创建技术架构、数据库设计、REST API 设计、AI 智能体方向、MVP 范围和开发规则。
- 定义中英文工程文档和业务审核规范。

### 架构影响

- 确定 Next.js、FastAPI、PostgreSQL、OpenAI Agents SDK、n8n 和 Docker 技术方向。
- 确立 PostgreSQL 为唯一正式业务事实来源。
- 采用模块化单体，并由确定性服务控制事务。
- 定义人工审批、可审计、租户隔离和窄权限 AI 工具边界。

### 业务影响

- 将初步构想转化为可实施、可审核的交付计划。
- 定义第一条完整流程：捕获线索、资格评估、跟进和转为商机。
- 缩小早期平台范围，使一个开发者或小团队能够交付可用 MVP。

## 2026-08-08 至 2026-08-09 — Phase 1：Sari Arta MVP

### 新增能力

- 上线双语 Sari Arta 公开网站和结构化询盘流程。
- 增加公司、联系人、线索、任务、活动和商机的认证 CRM 页面。
- 增加线索搜索、筛选、编辑、状态、负责人和公司/联系人关系管理。
- 增加仪表盘指标、跟进工作流和事务化线索转商机。
- 增加结构化 A/B/C AI 线索资格评估，包括业务摘要、关键因素、下一步建议和人工接受或拒绝。
- 增加持久化 Agent Run、有限重试、取消、恢复、Correlation ID、审计事件、合成演示数据和本地备份验证。

### 架构影响

- 实现 Next.js/FastAPI/PostgreSQL 模块化应用和 Docker Compose 运行环境。
- 增加 Redis 异步智能体执行，但不将 Redis 作为正式业务状态。
- 增加幂等公开询盘、乐观并发、行级安全、授权和审计基础。
- 将 AI 提供方失败与人工 CRM 操作分离。

### 业务影响

- 交付第一版可用的 Sari Arta 线索到商机工作流。
- 让销售人员可以在一个工作台中整理询盘、跟进工作和商机。
- 在不允许 AI 自主修改线索状态或作出商业承诺的情况下展示 AI 资格评估。

## 2026-08-09 至 2026-08-10 — Phase 2：多智能体框架

### 新增能力

- 增加领域、智能体、版本化配置、能力、本地化和租户启用的 Agent Registry 记录。
- 在 `commercial_kitchen` 下注册 Sari Arta 商用厨房智能体。
- 在 `laboratory_animal_facility` 下增加 IVC Facility Business Development Agent。
- 增加用于领域演示的英文、中文和 Bahasa Indonesia 资格评估输出。
- 增加 Agent Playground，可切换智能体并比较结构化资格评估结果，同时不修改 CRM 数据。

### 架构影响

- 将可复用智能体能力与领域专用配置分离。
- 引入受治理的领域包，而不是把每个新行业硬编码进 Phase 1 工作流。
- 在增加隔离的多领域演示时保留现有 Sari Arta 工作流。

### 业务影响

- 证明平台能够支持不止一个 B2B 行业。
- 将项目从单领域演示转变为可复用智能体框架。
- 创建可安全展示领域专业能力的作品集演示方式。

## 2026-08-12 — Phase 2.5.1：企业知识管理

### 新增能力

- 增加租户/领域知识集合、文档、元数据、生命周期状态和可选智能体绑定。
- 增加文档上传、列表、搜索、审核、批准、拒绝、启用和归档界面。
- 增加合成的商用厨房和 IVC 知识示例。

### 架构影响

- 建立独立的受治理知识控制面。
- 应用默认拒绝的租户、领域、智能体和集合访问边界。
- 保持文档管理与对话式 RAG 分离。

### 业务影响

- 为业务管理员提供准备企业知识的受控位置。
- 防止未经审核的上传内容自动成为智能体证据。

## 2026-08-14 — Phase 2.5.2：知识处理流水线

### 新增能力

- 增加 PDF、DOCX、Markdown 和 UTF-8 文本提取。
- 增加文本清洗、确定性分块、元数据保留和可引用来源信息。
- 增加嵌入提供方抽象，支持 OpenAI 兼容路径和确定性开发路径。
- 增加 pgvector 存储准备和异步处理状态。

### 架构影响

- 将已批准文档版本转换为按租户/领域/智能体隔离的 AI 就绪资产。
- 在处理过程中保留文档、版本、页码、章节、语言和 Chunk 标识。
- 将未来嵌入提供方置于稳定的应用边界之后。

### 业务影响

- 使已批准的企业文档在技术上可供未来基于证据的 AI 功能使用。
- 降低生成答案丢失来源上下文的风险。

## 2026-08-14 — Phase 2.5.3：知识治理

### 新增能力

- 增加不可变版本历史和明确的 current、published、active 版本指针。
- 增加替换版本、安全回滚、归档、恢复和绑定状态变更。
- 分离上传、编辑、提交审核、批准、发布、启用、归档、恢复、处理和审计权限。
- 增加包含操作人、时间戳、动作、目标和变更前后元数据的知识审计时间线。

### 架构影响

- 将文档存储升级为受治理的企业生命周期。
- 增加乐观并发和准确版本审批/发布控制。
- 确保批准不再自动意味着发布或启用。

### 业务影响

- 可以证明谁修改、批准、发布或回滚了业务知识。
- 降低智能体使用过期或未经批准文档的风险。

## 2026-08-16 — Phase 2.6：知识检索基础

### 新增能力

- 增加用于智能体范围 pgvector 相似度搜索的 `POST /api/v1/knowledge/search`。
- 增加 active、published、approved 版本、智能体绑定、语言和处理状态过滤。
- 增加完整文档/版本/页码/章节/Chunk 引用和明确的证据不足结果。
- 增加 Recall@K、Precision@K、Hit@1、MRR、引用、延迟、安全和双语一致性评估。
- 增加可重复回归数据集和显示阈值与分数的内部 `/knowledge/search` 测试界面。
- 随后增加建立在已验证检索边界上的只读商用厨房知识助手。

### 架构影响

- 在嵌入或模型调用前强制授权。
- 结合应用授权、PostgreSQL RLS 和默认拒绝的智能体绑定。
- 将正式证据与低于阈值的诊断结果分离。
- 为有依据回答建立证据充分、不充分和冲突处理方式。

### 业务影响

- 让内部人员可以查找带有可追溯来源的已批准企业证据。
- 为未来嵌入、分块、阈值和提供方变更建立可衡量的质量基线。
- 在没有 CRM 写入或自主动作的情况下展示安全的知识增强辅助。

## 2026-08-16 — Phase 3.1：公开项目咨询智能体

### 新增能力

- 在公开网站增加独立的英文/中文商用厨房项目咨询智能体。
- 增加引导式项目发现、联系方式收集、明确授权、来源记录、验证和防重复。
- 以 `website_ai_assistant` 来源复用现有 CRM 线索工作流。

### 架构影响

- 建立与内部知识助手分离的严格公开智能体信任边界。
- 将公开助手限制在公开信息范围，不提供内部知识、CRM 读取、价格或沟通工具。
- 增加独立限流、滥用控制和显式启用的外部模型路径。

### 业务影响

- 将公开网站转变为引导式线索生成体验。
- 让潜在客户可以准备有价值的项目简报，同时保留人工销售审核和授权。

## 2026-08-16 — Phase 3.2.3.4：受治理营销内容生成

### 新增能力

- 增加强类型中英文网站文章、TikTok、Instagram Reel、Facebook 和邮件草稿生成。
- 在统一生成契约后增加确定性 Mock 和 OpenAI 提供方适配器。
- 增加异步状态、公开证据引用、证据不足处理和营销工作台生成流程。
- 增加可重复的依据性、引用、结构、双语、禁止声明和知识边界评估。

### 架构影响

- 在一个受控运行时中连接 Agent Registry、`public_marketing_v1`、受治理检索、Agent Run、不可变内容版本和人工审核。
- 在嵌入、检索和模型调用前强制授权，同时保持生产激活待定。
- 为未来 Qwen 或经批准的私有/本地适配器保留提供方可移植性。

### 业务影响

- 员工可以依据已批准公开证据生成可审核的 B2B 营销草稿，不必从空白页面开始。
- 来源可追踪和强制人工批准降低无依据营销声明风险，同时不开放发布或外部发送。

## 2026-08-16 — Phase 3.2.4A：自然搜索与 AI 搜索技术基础

### 新增能力

- 增加明确的公开/私有爬虫边界、标准页面 Metadata 和私有路由 `noindex` 控制。
- 增加可维护的 Robots 和 Sitemap 策略，并明确审核 Googlebot、Bingbot 和 OAI-SearchBot。
- 增加 Organization、WebSite 和 Breadcrumb 结构化数据，以及可复用的未来发布模式。
- 增加默认禁用的 IndexNow 就绪能力和 Google/Bing 验证配置点。
- 增加最小化的自然搜索、AI 搜索、直接、社交和 Referrer 归因，同时保留现有 CRM 录入来源。

### 架构影响

- 集中管理公开路由资格，使 Sitemap、IndexNow、Canonical URL 和未来受治理发布使用相同的默认拒绝边界。
- 增加服务端渲染中英文 Metadata 和不绑定供应商的机器可读站点身份，不使用爬虫专用内容。
- 搜索管理平台、生产域名激活、Analytics 和发布触发器保持在应用默认行为之外。

### 业务影响

- 让当前 Sari Arta 公开网站在技术上具备自然搜索和 AI 搜索发现能力。
- 把未来搜索发现连接到现有授权咨询与 CRM 录入路径，同时不改变 CRM 工作流。
- 保留延期的 Phase 3.2 业务验收门槛：没有激活或发布任何生成营销内容。

## 当前状态

平台已经从单一业务演示发展为可复用的企业级 AI 商务拓展平台。当前系统结合了可运营 CRM 工作流、多领域智能体框架、受治理企业知识生命周期、经过评估的检索、只读有依据辅助、独立的公开项目咨询体验、受治理营销草稿生成，以及自然搜索与 AI 搜索技术基础。外部沟通自动化、自主销售动作、生成内容生产激活和高级智能体编排仍属于未来受控阶段。
